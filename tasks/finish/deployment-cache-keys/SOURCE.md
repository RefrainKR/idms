# 배포 캐시 키 자동화 원문 요약

2026-08-29 공개 v1.12.1에서 `main.js?v=1.12.1`이 새로운 파일로 갱신됐지만, 쿼리가 없는 하위 `StorageManager.js`가 브라우저의 이전 캐시에서 로드되어 `StorageManager.clearAll is not a function` 오류가 발생했습니다.

긴급 v1.12.2에서는 영향을 받는 import 경로마다 `?v=1.12.2`를 수동으로 추가해 해결했습니다. 그러나 버전마다 HTML, CSS 참조, 여러 단계의 JavaScript import를 사람이 모두 수정하는 방식은 작업량과 누락 위험이 큽니다.

사용자는 다음 방식을 시험 구현하도록 승인했습니다.

- VS Code와 GitHub 저장소의 원본에서는 `?v=`를 제거하고 깨끗한 상대경로를 유지합니다.
- GitHub Actions가 Jekyll 배포 사본을 만든 뒤 로컬 JS/CSS 참조에 현재 커밋 SHA를 자동으로 붙입니다.
- 외부 CDN 주소는 변경하지 않습니다.
- 모든 대상 참조가 변환됐는지 자동 검사합니다.
- 이번 단계는 비공개 작업 브랜치에서 검증하며, 별도 승인 없이 `main`에 반영하지 않습니다.
