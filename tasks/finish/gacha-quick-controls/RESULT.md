# 결과

> 이 문서는 첫 시안 결과와 이후 반복 검토를 누적합니다. 첫 시안은 사용자 최종 승인을 받지 않았으며 작업은 진행 중입니다.

## 구현 결과

- 3성의 기존 사용자 입력 5개를 복제하지 않고 결과 바로 앞의 `빠른 설정` 바로 이동했습니다.
  - 대상 전환: `star3-targetMode-btn`
  - 픽업 수: `star3-targetCount`
  - 일반 횟수: `star3-normalPulls`
  - 스탭업 횟수: `star3-stepPulls`
  - 목표 확률: `star3-targetProbability`
- 빠른 설정 바는 `sub-tab-system-3star` 직전, `tab-3star` 섹션 안에 위치하며 `position: sticky; top: 12px`로 동작합니다.
- `controlVisibility` 규칙을 추가해 다음처럼 원래 입력 wrapper만 전환합니다.
  - 픽업 획득·총 획득: 대상, 픽업 수, 일반, 스탭업
  - 일반 vs 스탭업: 대상, 픽업 수, 목표 확률
  - 무돌: 일반, 스탭업
- 빠른 설정은 데스크톱 네 열 한 줄, 390px 모바일 두 열·최대 두 줄이며 모바일 높이는 모든 서브탭에서 106px로 같습니다.
- `APP_VERSION`과 정적 자산 캐시 키를 `1.12.1`로 갱신했습니다.
- 확률 계산 Core, 게임 규칙, Observable 모델, InputBinder 구현은 변경하지 않았습니다.

## 검증 결과

- `git diff --check` 통과
- `node --check scsfp/js/view/gacha/GachaViewConfig.js` 통과
- `node --check scsfp/js/core/Constants.js` 통과
- 이동한 5개 ID가 `index.html`에 각각 한 번만 존재함을 확인
- headless Chromium CDP 검증:
  - 3성 4개 서브탭의 빠른 설정 표시 목록이 결정 문서와 일치
  - 390px viewport에서 문서 가로폭 390px, 빠른 설정 폭 350px으로 전역 가로 넘침 없음
  - 4개 서브탭의 빠른 설정 높이가 모두 106px
  - `normalPulls=40`, target mode 전환, target count/step-up 상한 clamp, target probability 변경 시 실제 ViewModel·InputBinder 경로의 요약 재계산 및 LocalStorage 저장 확인
  - `top: 12px` sticky 위치 확인
- Terra 샌드박스에서는 jsDelivr CDN에 연결할 수 없어 Chart constructor stub으로 계산·표시 제어·입력 바인딩 경로를 검증했습니다. 이후 Sol이 샌드박스 밖의 격리된 headless Chrome에서 실제 CDN Chart.js 차트 렌더링을 추가 확인했습니다.

## Sol 최종 검토

- TASK/DECISIONS 범위와 실제 diff가 일치하며 확률 계산 및 게임 규칙 변경은 없습니다.
- 이동한 입력 ID 5개는 각각 한 번만 존재하고 기존 Observable·InputBinder 계약을 유지합니다.
- 독립 CDP 검증에서 390×844 viewport의 문서 폭 390px, 빠른 설정 폭 350px, 모든 서브탭 높이 106px을 확인했습니다.
- 픽업 획득·총 획득·일반 vs 스탭업·무돌의 표시 항목이 결정 문서와 일치합니다.
- 샌드박스 밖의 격리된 headless Chrome에서 실제 CDN Chart.js 차트 렌더링도 확인했으며 수정 요청 없이 승인했습니다.

## 남은 기술 부채

- 생일·콜라보·2성은 이번 첫 적용 범위에 포함하지 않았습니다. 공통 CSS와 visibility helper는 향후 별도 승인 작업에서 재사용할 수 있습니다.
- 실제 모바일 기기의 숫자 키보드 사용감은 개발자 확인 단계에서 추가로 살펴볼 수 있습니다.

## 2차 시안 — 1안

### 변경 결과

- 3성 `가챠 정보`는 `픽업 수 · 개별 확률 · 주회 · Step4 · 주회 보상`을 한 줄로 보여주고, `가챠 설정` native dialog에서 기존 원본 입력을 편집합니다. Observable 구독으로 직접 입력·프리셋·LocalStorage 복원 값이 요약에 반영됩니다.
- `빠른 설정`은 서브탭 아래의 압축 영역에 두고 `option-button-container`는 결과 콘텐츠 바로 위의 별도 무배경 행으로 유지했습니다. 원본 입력은 복제하지 않았습니다.
- 픽업 획득 모바일은 `차트 / 확률표` 전환으로 차트와 범례를 같은 결과 공간에서 교체합니다. `Step4 확률`은 계산 토글로 그대로 분리했습니다.
- 네 결과 탭은 모바일 430px, 데스크톱 420px의 고정 `result-stage` 안에서 바뀌며 긴 내용은 내부 스크롤합니다. 3성 활성 시 공용 결과 요약에도 최소 높이를 주어 남는 문서 높이 변동을 완화했습니다.

## 2차 시안 — 1안 보완 기록

Sol의 실제 CDN Chrome 390×844 검토에서 공용 `gacha-result-area`가 탭별로 문서 높이를 늘리는 문제가 확인됐습니다. 보완 전 전체 문서 높이는 픽업 획득 1116px, 총 획득 1048px, 일반 vs 스탭업 1048px, 무돌 1521px이었습니다. 또한 모바일 결과 제어는 일반 탭 약 110px, 무돌 약 104px로 달랐습니다.

- 3성 활성 중 공용 결과 요약/상세 영역을 148px 고정 내부 스크롤 영역으로 전환했습니다.
- 모바일 결과 제어를 110px으로 고정했습니다.
- Chart stub CDP 390×844 재검증에서 네 탭의 전체 문서 높이는 모두 1047px, 결과 제어는 110px, 결과 스테이지는 430px, 공용 요약 영역은 148px이었습니다. 문서 폭은 모두 390px입니다.
- 활성 수집 탭에서 차트 보기의 범례는 computed `display: none`, 0×0px이고 차트는 `flex`, 350×350px입니다. 확률표 보기에서는 반대로 차트가 `none`, 0×0px이고 범례가 `block`, 350×210px입니다.

실제 Chart.js CDN 렌더링에서의 최종 수치는 Sol 재검토 대상이며, 이 기록은 앞선 측정값을 대체하지 않고 보완 이력으로 누적합니다.

## 2차 시안 — 사용자 조정 결과

- 옵션 행을 `star3-result-controls` 밖으로 옮겨 결과 콘텐츠 바로 위에 배치하고 배경·테두리가 없는 기존 표현을 복원했습니다.
- `상세 설정`을 `가챠 설정`으로 변경하고 dialog 하단 닫기 버튼을 제거했습니다.
- `.sub-tab-container`의 `margin-top`을 15px로 조정했습니다.
- PC의 가챠 메인 탭, 배너 요약, 가챠 설정 버튼과 빠른 설정 글꼴을 모두 0.85rem로 맞췄습니다.
- dialog 제목은 1rem로 유지했습니다.
- 실제 CDN Chrome 검증에서 옵션 행은 `sub-tab-system-3star`의 직접 자식이며 투명 배경·테두리 없음으로 확인했습니다.
- 1280×900에서 네 탭의 문서 높이는 모두 950px, 390×844에서는 모두 1059px이었습니다. 모바일 전역 가로폭은 390px입니다.

## 배너 요약·프리셋·전체 초기화 보완 결과

- PJ 프리셋의 배너 요약을 `4명, 1% / 3주, 40%, 2주:랜덤, 3주:셀렉`으로 압축했습니다.
- 3성 프리셋을 가챠 설정 dialog의 기본 정보 위로 옮기고 위·아래 여백을 각각 10px로 맞췄습니다.
- `star3-reset-btn`과 Star3 ViewModel의 개별 초기화 연결을 제거했습니다. 새 `app-reset-all-btn`은 공통 `main.js`에서 확인 후 `StorageManager.clearAll()`을 실행하고 다시 불러옵니다.
- 데스크톱 1280×900에서 초기화 버튼은 200px 사이드바 내부의 아래쪽 16px 위치, 모바일 390×844에서는 상단 메뉴 오른쪽에 있음을 실제 Chrome에서 확인했습니다.
- PC의 `확률표` 버튼은 `display: none`, 모바일에서는 표시되어 `확률표 → 차트`로 실제 전환됐습니다.
- 브라우저 LocalStorage에 임시 키 두 개를 추가한 뒤 전체 초기화를 실행해 두 키가 모두 삭제되고, 재로딩 후 현재 버전용 `app_version`만 다시 생성되는 것을 확인했습니다.
- `git diff --check`과 수정 JavaScript 세 파일의 `node --check`을 통과했습니다.

## 생일·콜라보·2성 확장 결과

- 생일·콜라보·2성의 큰 가챠 정보/사용자 설정 영역을 짧은 배너 요약, 공통 가챠 설정 dialog와 결과 인접 빠른 설정으로 재배치했습니다.
- 생일 기본 요약은 `1명 / 일반 1.5%, 스탭업 2% / 스탭업 30회`, 콜라보는 `5명 / 일반 0.75%, 스탭업 1%`, 2성은 `28명, 전체 28% / A:8, B:7, C:7, D:6` 형식입니다.
- 2성의 그룹별 스탭업 횟수와 저격 수는 A–D 경계를 유지했으며, 효율 탭에서는 계산에 필요한 저격 수만 표시합니다.
- 공통 dialog와 모바일 차트/확률표 전환을 BaseGachaViewModel로 옮겨 네 ViewModel의 중복 UI 이벤트를 제거했습니다.
- 실제 CDN Chart.js를 사용한 Chromium에서 네 가챠의 collection 차트 생성, dialog 내부/배경 클릭 구분, 데스크톱 420px·모바일 430px 결과 스테이지를 확인했습니다.
- 데스크톱에서 빠른 설정 높이는 3성·생일·콜라보가 전 탭 45.625px, 2성이 전 탭 133px이었습니다. 모바일은 각각 76px과 162px으로 고정됐습니다.
- 390px 모바일에서 네 가챠 모두 전역 가로 넘침이 없고 차트/확률표가 실제로 교체됐습니다. 데스크톱에서는 전환 버튼이 숨겨지고 가로 넘침이 없습니다.
