# 가챠 그래프 연동 빠른 설정 UI

- 상위 색인: [NEXTROAD.md](../../../NEXTROAD.md)
- 항목 번호: 1
- 상태: v1.12.1 완료 기록
- 대상 버전 계열: `v.1.12.X`
- 구현 승인: 2026-08-29 완료 및 main 반영 승인
- 마지막 정리: 2026-08-29

## 문제

현재 3성 가챠에서 사용자가 자주 바꾸는 값은 결과 그래프보다 위쪽의 `사용자 설정` 접이식 영역에 있습니다.

- 저격 ↔ 아무나
- 목표 픽업 수
- 일반 횟수
- 스탭업 횟수
- 효율 탭의 목표 확률

사용자가 `픽업 획득(중복X)` 그래프를 보면서 이 값들을 여러 번 조정하려면 설정 영역과 그래프 사이를 계속 스크롤해야 합니다. 실제 사용 중 반복적으로 발생하는 불편이므로 새로운 분석 표보다 먼저 해결합니다.

## 우선순위

이 항목은 계산 결과를 추가하는 기능이 아니라 기존 계산기의 기본 반복 조작을 개선하는 작업입니다.

1. 그래프 연동 빠른 설정 UI
2. [스탭업 주요 구간별 효과 표](NEXTROAD_02_STEPUP_CHECKPOINTS.md)
3. 나머지 분석 후보

## 목표

- 사용자가 그래프를 보는 위치에서 주요 조건을 즉시 바꿀 수 있어야 합니다.
- 서브탭을 전환해도 `sub-tab-nav → option-button-container → 결과 콘텐츠`의 위치가 자연스럽게 유지돼야 합니다.
- 같은 모델 값을 편집하는 입력을 위아래에 중복 생성하지 않습니다.
- 현재 Observable, InputBinder, LocalStorage와 입력 제한 동작을 유지합니다.
- 데스크톱과 모바일에서 전역 가로 스크롤이나 과도한 화면 가림이 없어야 합니다.

## 설정의 역할 분리

### 배너 규칙에 가까운 설정

기존 `가챠 정보` 접이식 영역에 유지합니다.

- 픽업 개수
- 개별 픽업 확률
- 최대 주회 수
- Step4 픽업 확률
- 주회별 보상

### 그래프를 보며 반복 조정하는 설정

작은 `빠른 설정 바`로 이동하는 방안을 우선 검토합니다.

- 저격 ↔ 아무나
- 목표 픽업 수
- 일반 횟수
- 스탭업 횟수
- 목표 확률

기존 `사용자 설정`의 입력 요소를 복제하지 않고 원래 ID를 유지한 채 빠른 설정 바로 이동하는 방식이 우선안입니다.

## 권장 위치

빠른 설정 바는 `sub-tab-system-3star` 바로 앞에 둡니다.

```text
[프리셋 / 초기화]

[가챠 정보 — 접기/펼치기]

[빠른 설정 바]

[픽업 획득] [총 획득] [일반 vs 스탭업] [무돌]
[기존 옵션 버튼]
[현재 결과 콘텐츠]
```

이렇게 하면 서브탭 내부의 기존 배치 순서를 변경하지 않고, 빠른 설정 바의 높이만 일정하게 유지해 탭 전환 시 그래프가 위아래로 움직이는 현상을 줄일 수 있습니다.

## 고정 표시 방식

그래프를 내려보는 동안 빠른 설정 바가 화면 상단에 남는 `position: sticky` 방식을 우선안으로 검토합니다.

- sticky 범위는 현재 활성 가챠 섹션 내부로 제한합니다.
- 가챠 섹션을 벗어나 과금 효율 영역까지 따라가지 않아야 합니다.
- 배경색, 테두리 또는 그림자로 그래프와 구분합니다.
- 다른 고정 요소와 겹치지 않도록 실제 데스크톱·모바일 화면에서 `top`과 `z-index`를 검증합니다.
- 모바일 숫자 키보드가 열린 상태에서도 입력과 그래프가 지나치게 가려지지 않아야 합니다.

전체 `사용자 설정` 패널을 큰 상태로 고정하면 모바일 화면을 과도하게 차지하므로 사용하지 않습니다.

## 서브탭별 표시 후보

빠른 설정 바의 전체 높이는 유지하면서 현재 서브탭에 필요한 항목만 보여주는 방향입니다.

### 픽업 획득(중복X)

```text
[저격↔아무나] [픽업 수] [일반 횟수] [스탭업 횟수]
```

### 총 획득(중복O)

```text
[저격↔아무나] [픽업 수] [일반 횟수] [스탭업 횟수]
```

총 획득 분포에서 저격/아무나와 목표 픽업 수가 정확히 어떤 의미를 갖는지는 현재 계산 경로를 다시 확인한 뒤 최종 표시 항목을 확정합니다.

### 일반 vs 스탭업

```text
[저격↔아무나] [픽업 수] [목표 확률]
```

직접 입력한 일반·스탭업 횟수는 전략 비교 곡선에 사용되지 않으므로 효율 탭에서는 숨기는 방안을 우선 검토합니다. 목표 확률 입력은 현재 차트 아래가 아니라 같은 높이의 빠른 설정 바에 표시합니다.

### 무돌

```text
[일반 횟수] [스탭업 횟수]
```

무돌 계산에 사용되지 않는 저격/아무나와 목표 픽업 수는 숨기는 방안을 우선 검토합니다.

## 데스크톱 배치 후보

```text
[저격] [픽업 수 2] [일반 0] [스탭업 80]
```

각 입력은 기존 큰 설정 카드보다 작게 표시하되 라벨과 단위가 구분돼야 합니다. 숫자 입력 폭은 실제 허용 범위를 고려해 고정하거나 상한을 둡니다.

## 모바일 배치 후보

가능하면 한 줄, 공간이 부족하면 높이가 일정한 두 줄을 사용합니다.

```text
[저격] [픽업 2] [일반 0] [스탭업 80]
```

또는:

```text
[저격] [픽업 2]
[일반 0] [스탭업 80]
```

빠른 설정 바 자체가 페이지 전체의 가로 스크롤을 만들면 안 됩니다. 입력을 단순히 가로 스크롤 영역에 넣는 방식은 마지막 대안으로만 검토합니다.

## UI와 CSS 책임

- 3성 전용 위치값을 늘어놓기보다 다른 가챠에서도 재사용할 수 있는 빠른 설정 컨테이너와 작은 숫자 제어 스타일을 만듭니다.
- 기존 `.input-item`은 일반 설정 패널용이므로 그대로 축소 적용하지 않고, 용도가 분명한 공통 클래스를 검토합니다.
- 클래스 이름 후보는 구현 시 실제 역할을 기준으로 결정하며 이 문서의 후보명을 기계적으로 사용하지 않습니다.
- 기존 `option-button-container`는 계산 토글과 보기 모드를 유지하고, 빠른 설정 값까지 모두 밀어 넣어 과밀하게 만들지 않습니다.
- 탭별 표시 대상은 현재 `buttonVisibility`와 유사한 설정 기반 구조로 관리하되, 입력까지 관리한다면 `controlVisibility`처럼 의미가 맞는 이름으로 소규모 정리할 수 있습니다.

## 데이터 연결 원칙

- 기존 입력 ID와 Observable을 유지하는 방안을 우선합니다.
- 동일한 값을 편집하는 입력 요소를 복제하지 않습니다.
- 프리셋, 초기화, LocalStorage 복원 시 이동한 입력도 현재와 동일하게 갱신돼야 합니다.
- `targetCount`의 픽업 수 상한과 `stepPulls`의 Step-up 최대 횟수 제한을 유지합니다.
- 저격/아무나 버튼의 현재 상태와 문구가 모델과 항상 일치해야 합니다.
- 입력 위치 변경 때문에 계산 시점이나 확률 알고리즘을 수정하지 않습니다.

## 첫 적용 범위 후보

우선 3성 가챠에서 구조와 사용성을 검증합니다.

- 기존 `사용자 설정`의 자주 쓰는 입력을 빠른 설정 바로 이동
- 서브탭별 관련 입력 표시
- 그래프를 보며 값을 변경할 수 있는 sticky 동작
- 목표 확률 입력 접근성 개선
- 데스크톱 및 모바일 레이아웃 검증

생일·콜라보·2성은 공통 스타일과 제어 구조를 재사용할 수 있도록 설계하되, 첫 구현에 함께 포함할지는 별도로 결정합니다.

## 추가로 결정할 사항

1. 빠른 설정 바를 실제로 sticky로 고정할지, 결과 영역 바로 앞에만 배치할지
2. 모바일에서 한 줄과 두 줄 중 어느 쪽을 기본으로 할지
3. 서브탭별 표시 후보가 실제 계산 의존성과 일치하는지
4. 첫 구현을 3성으로 제한할지, 생일·콜라보·2성까지 함께 정리할지
5. 빠른 설정 바의 라벨을 `픽업 수`, `일반`, `스탭업`, `목표 확률` 중 어느 길이로 표시할지
6. sticky 상태를 시각적으로 얼마나 강조할지

## 현재 결론

그래프와 설정 영역을 반복해서 오가는 문제는 주요 구간 표보다 먼저 해결할 가치가 있습니다. 빠른 설정 바가 우선안이지만 sticky 동작, 모바일 배치와 첫 적용 범위를 추가 검토한 뒤 구현을 승인합니다. 이 문서는 아직 구현 승인 문서가 아닙니다.

## 2026-08-29 1차 시안 검토 결과

첫 시안은 기존 사용자 설정 입력을 106px 높이의 sticky 빠른 설정 카드로 옮겼습니다. 입력 접근성은 좋아졌지만 `가챠 정보 → 빠른 설정 → 서브탭 → 옵션 → 차트 → 범례`가 문서 흐름에 계속 누적되어 세로 스크롤을 충분히 줄이지 못했습니다.

따라서 첫 시안을 최종안으로 확정하지 않고 다음 세 구조를 비교합니다. 이 01 문서는 반복 시안과 사용자 의견을 계속 축적하며, 사용자가 명시적으로 완료를 선언하기 전에는 삭제하거나 `tasks/finish/`로 끝내지 않습니다.

### 1안: 고정 결과 스테이지 + 압축 제어 바 — 현재 실험안

```text
[3성 | 생일 | 콜라보 | 2성]
[정규 · 픽업 2 · 개별 1% · 2주] [가챠 설정]
[픽업 획득 | 총 획득 | 일반 vs 스탭업 | 무돌]
[저격 | 픽업 2 | 일반 0 | 스탭업 0]
[천장] [랜덤 티켓] [Step4]      [차트 | 확률표]
┌────────────────────────────┐
│ 고정 높이 결과 스테이지     │
└────────────────────────────┘
```

- 기존 큰 `가챠 정보`는 현재 배너 규칙을 보여주는 한 줄 요약과 `가챠 설정` 진입 버튼으로 바꿉니다.
- 상세 배너 규칙 입력은 페이지 높이를 늘리지 않는 dialog/drawer 계열 오버레이에서 편집합니다.
- 빠른 설정은 서브탭 아래의 압축 영역에 두고, 옵션 행은 그 바깥에서 기존처럼 배경·테두리 없는 `option-button-container`로 결과 콘텐츠 바로 위에 둡니다.
- 모바일의 픽업 획득 차트와 범례는 같은 공간에서 `차트 / 확률표`로 전환합니다.
- `star3-toggle-step4`는 계산 포함 여부이므로 보기 전환 용도로 재사용하지 않습니다.
- 서브탭 콘텐츠 바깥 높이를 일정하게 유지하고, 긴 콘텐츠는 결과 스테이지 내부에서 스크롤합니다.
- 데스크톱에서는 차트와 범례를 나란히 유지할 수 있지만 결과 시작 위치와 전체 높이는 안정적으로 유지합니다.

장점은 그래프와 반복 입력을 동시에 보면서 세로 길이와 탭 전환 흔들림을 줄일 수 있다는 점입니다. 단점은 무돌처럼 내용이 긴 화면에서 내부 스크롤이 생길 수 있다는 점입니다.

### 2안: 설정·결과 가로 페이지 전환

```text
[설정 | 결과]

설정: 가챠 정보 + 사용자 입력
결과: 서브탭 + 옵션 + 고정 결과 영역
```

- 모바일에서는 설정과 결과를 동일 높이의 가로 페이지 또는 스와이프 패널로 나눕니다.
- 데스크톱에서는 설정과 결과의 2열 레이아웃으로 확장할 수 있습니다.
- 세로 길이는 예측하기 쉽지만 값을 바꾸며 그래프를 동시에 보는 흐름은 1안보다 약합니다.

### 3안: 하단 고정 설정 도크 + 바텀 시트

```text
[서브탭 / 옵션]
[결과 스테이지]

[저격 · 픽업 2 · 일반 0 · 스탭 0]  ← 하단 고정
```

- 결과를 화면 중심에 두고 설정 요약 도크를 화면 하단에 고정합니다.
- 도크를 누르면 빠른 설정, 가챠 정보와 주회 보상을 포함한 바텀 시트가 열립니다.
- 세로 스크롤은 가장 적지만 키보드, 포커스, 뒤로가기, 데스크톱 대응까지 필요해 구현 복잡도가 가장 큽니다.

## 현재 1안 실험 범위

- 3성 화면만 대상으로 기존 첫 시안을 재구성합니다.
- 가챠 정보는 한 줄 배너 요약 + `가챠 설정` 오버레이로 바꿉니다.
- 빠른 설정은 압축 영역으로 구성하고 옵션 버튼은 별도의 기존형 무배경 행으로 유지합니다.
- 픽업 획득 모바일 화면에 `차트 / 확률표` 전환을 추가합니다.
- 서브탭별 결과 영역의 외부 높이를 일정하게 유지합니다.
- 기존 입력 ID, Observable, InputBinder, 프리셋, 초기화와 LocalStorage 계약은 유지합니다.
- 계산 Core, 게임 규칙, 분석 지표는 변경하지 않습니다.
- 1안 구현 결과는 최종 완료가 아니라 다음 사용자 검토를 위한 실험 시안입니다.

## 2026-08-29 배너 요약·프리셋·초기화 조정

- 배너 요약은 설명형 문장 대신 `4명, 1% / 3주, 40%, 2주:랜덤, 3주:셀렉`처럼 짧게 표시합니다.

- PC에서는 차트와 확률표가 나란히 보이므로 `확률표` 전환 버튼을 계속 숨깁니다. 이 버튼은 모바일에서만 차트와 확률표를 실제로 교체합니다.
