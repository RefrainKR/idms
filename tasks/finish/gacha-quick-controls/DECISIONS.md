# 결정 사항

## 2차 실험 결정 — 1안

아래 범위는 첫 sticky 카드 시안 당시의 결정 기록입니다. 이후 `DISCUSSION.md`의 1안으로 재구성하고 사용자 피드백을 거쳐 v1.12.1로 완료했습니다.

- 3성 화면만 변경합니다.
- 배너 규칙 입력은 한 줄 요약과 `가챠 설정` 오버레이로 재배치하되 기존 ID와 바인딩을 유지합니다.
- 빠른 설정은 압축 영역에 배치하고 계산/보기 옵션은 결과 콘텐츠 바로 위의 별도 무배경 `option-button-container`에 유지합니다.
- 모바일 픽업 획득 화면은 별도의 `차트 / 확률표` 보기 전환을 사용합니다. 계산 토글인 `Step4 확률`을 보기 전환에 재사용하지 않습니다.
- 서브탭 결과 영역은 고정된 외부 높이를 사용하고 긴 내용만 내부 스크롤합니다.
- 결과 요약 영역을 포함해 탭 전환 시 문서 높이가 크게 달라지는 원인을 확인하고, 범위 내에서 안정화합니다.
- 확률 계산과 게임 규칙은 변경하지 않습니다.
- 이 구현은 사용자 비교용 시안이므로 Sol 검토 뒤에도 `done`으로 처리하지 않습니다.

## 확정 범위

- 첫 구현은 3성 가챠로 제한합니다.
- 배너 규칙 입력은 기존 `가챠 정보` 접이식 영역에 유지합니다.
- 기존 `사용자 설정` 입력을 복제하지 않고 원본 DOM 요소와 ID를 빠른 설정 바로 이동합니다.
- 빠른 설정 바는 `sub-tab-system-3star` 바로 앞에 두고 현재 3성 가챠 섹션 안에서 sticky로 동작시킵니다.
- 기존 `sub-tab-nav → option-button-container → 결과 콘텐츠` 순서는 유지합니다.
- 데스크톱은 한 줄을 우선하고, 모바일은 가로 넘침 없이 필요하면 최대 두 줄로 배치합니다.
- 빠른 설정 바의 높이는 서브탭별 표시 항목이 달라도 안정적으로 유지합니다.

## 서브탭별 제어

- 픽업 획득: 저격/아무나, 목표 픽업 수, 일반 횟수, 스탭업 횟수
- 총 획득: 저격/아무나, 목표 픽업 수, 일반 횟수, 스탭업 횟수
- 일반 vs 스탭업: 저격/아무나, 목표 픽업 수, 목표 확률
- 무돌: 일반 횟수, 스탭업 횟수

총 획득 계산은 현재 target mode/count의 영향을 받으므로 두 제어를 유지합니다. 효율 곡선은 직접 입력한 일반·스탭업 횟수를 사용하지 않으므로 해당 탭에서는 숨깁니다.

## 구현 원칙

- 현재 InputBinder와 Observable 연결을 유지합니다.
- 탭별 표시를 위해 입력 wrapper를 제어할 수 있지만 입력 자체를 새로 만들지 않습니다.
- 기존 버튼 전용 `buttonVisibility`가 입력 wrapper까지 관리하게 된다면 의미가 맞는 `controlVisibility` 계열 이름으로 제한적으로 정리합니다.
- sticky 동작은 CSS를 우선하며 불필요한 스크롤 이벤트 로직을 추가하지 않습니다.
- 공통 스타일은 다른 가챠에서 재사용할 수 있게 만들되, 이번 구현에서 다른 가챠 DOM까지 이동하지 않습니다.
- 확률 계산 Core는 수정하지 않습니다.

## 검증 결정

- 390×844 모바일과 데스크톱에서 실제 브라우저 검증을 수행합니다.
- 모든 3성 서브탭의 visibility와 레이아웃을 확인합니다.
- 입력 변경, 프리셋, 초기화, LocalStorage 복원을 확인합니다.
- 대표 계산 결과를 기준 커밋과 비교합니다.

## 배너 요약·프리셋·초기화 추가 결정

- 배너 요약은 `인원, 개별 확률 / 주회, Step4 확률, 주회:보상` 순서의 짧은 한국어 표현을 사용합니다.
- 3성 프리셋은 `가챠 설정` dialog의 `기본 정보` 위에 둡니다.
- 기존 3성 `↻`는 개별 모델 초기화가 아니라 앱 전체 설정 초기화입니다. `StorageManager`가 LocalStorage 전체 삭제를 담당하고 앱 공통 초기화 코드가 확인·재로딩을 담당합니다.
- 전체 초기화 버튼은 데스크톱 사이드바 하단, 모바일 상단 메뉴 오른쪽에 둡니다.
- `확률표` 전환은 모바일 전용으로 유지하고 데스크톱에서는 표시하지 않습니다.

## 생일·콜라보·2성 확장 결정

- 초기의 3성 한정 적용은 사용자 승인에 따라 네 가챠 공통 적용으로 확장합니다.
- 공통 dialog 열기·닫기와 모바일 차트/확률표 전환은 BaseGachaViewModel의 UI 보조 메서드로 관리합니다.
- 생일·콜라보는 3성과 같은 압축 입력 그리드를 사용합니다.
- 2성은 A–D 그룹 경계를 평면 입력으로 합치지 않고 그룹 행을 유지하며, 탭별 표시 항목이 달라도 컨테이너 높이를 고정합니다.
- 기존 입력 ID, Observable, InputBinder와 계산 순서는 변경하지 않습니다.
