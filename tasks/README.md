# 작업 문서 운영 규칙

이 디렉터리는 구현이 승인된 작업의 계획·결정·인수인계·검증을 보존하는 코딩 에이전트용 작업 공간입니다. 개발 아이디어를 논의하는 장소는 저장소 루트의 `NEXTROAD.md`입니다.

저장소가 public이므로 “에이전트용”은 편집 책임을 뜻할 뿐 비공개를 뜻하지 않습니다. 비밀번호, 토큰, 비공개 개인정보를 작업 문서에 기록하지 않습니다.

## 역할

- **Sol 역할**: 아이디어 및 게임 규칙 검토, 범위와 완료 조건 결정, 실제 diff 최종 검토
- **Terra 역할**: 승인된 범위 구현, 기계적 리팩토링, 테스트, 구현 결과 기록
- Terra가 규칙이나 범위를 확정할 수 없으면 추측하지 않고 `HANDOFF.md`에 질문을 기록한 뒤 Sol 역할로 반환합니다.

모델 버전이 바뀌어도 역할 의미는 유지합니다. 현재 모델명보다 `BOARD.md`와 작업 문서의 역할·상태가 우선합니다.

## 논의에서 구현으로 전환

1. 개발자와 Sol은 `NEXTROAD.md`에서 다음 작업을 논의합니다.
2. 개발자가 구현 시작을 명시하기 전에는 task packet이나 코드 변경을 만들지 않습니다.
3. 구현 시작 시 `main`이 아닌 올바른 버전 계열 브랜치를 먼저 확인합니다.
4. 합의된 `NEXTROAD.md` 전체를 새 `tasks/<작업명>/SOURCE.md`에 복사해 원문을 보존합니다.
5. `SOURCE.md`와 원문이 동일하게 보존됐는지 확인한 뒤 `NEXTROAD.md`를 `_template/NEXTROAD.md` 내용으로 초기화합니다.
6. `TASK.md`와 `DECISIONS.md`에 허용 범위·금지 범위·완료 조건을 확정하고 `ready-for-terra`로 전환합니다.

## 작업별 기본 파일

- `SOURCE.md`: 구현 시작 직전 합의된 `NEXTROAD.md` 원문
- `TASK.md`: 목적, 허용·금지 범위, 완료 조건, 버전과 브랜치
- `DECISIONS.md`: Sol 역할이 확정한 규칙과 설계 판단
- `HANDOFF.md`: 완료 사항, 남은 작업, 변경 파일, 검증, 질문, 다음 역할
- `RESULT.md`: 구현 및 최종 검토 결과

새 작업은 `_template/`을 복사해 작업별 디렉터리로 시작합니다.

## 상태 전이

`planning` → `ready-for-terra` → `implementing` → `ready-for-sol-review` → `changes-requested` → `done`

- 상태와 다음 역할은 `BOARD.md`와 해당 작업의 `TASK.md`에 함께 반영합니다.
- 역할을 바꾸기 전에 반드시 `HANDOFF.md`를 갱신합니다.
- 문서에 아이디어가 있다는 사실만으로 구현이 승인된 것은 아닙니다.
- `done`은 코드·문서 반영, 필요한 검증, Sol 역할의 최종 검토가 모두 끝난 경우에만 사용합니다.

## 버전과 Git

- `main`은 공개 GitHub Pages에 바로 반영되는 실서비스 브랜치이므로 개발 작업을 하지 않습니다.
- 버전은 `1.<major>.<minor>`, 브랜치는 `v.1.<major>.X` 형식입니다. 맨 앞의 `1`을 바꾸는 판단은 개발자만 합니다.
- 새 기능이나 기존 기능의 의도적 교체는 `<major>`를 올려 `1.11.0 → 1.12.0`, `v.1.12.X`처럼 시작합니다.
- 버그, 의도와 달라진 결과, 소규모 문구·세부 변경은 `<minor>`를 올려 `1.11.0 → 1.11.1`처럼 같은 `v.1.11.X` 브랜치에서 진행합니다.
- 같은 작업 트리의 같은 파일을 Sol과 Terra가 동시에 수정하지 않습니다. 기본은 하나의 작업 브랜치에서 순차 인계입니다.
- 실제 동시 구현은 개발자가 승인한 별도 브랜치와 worktree에서만 진행하며 먼저 파일 소유 범위를 나눕니다.
- 커밋, push, `main` 병합, 배포는 개발자가 직접 판단하고 수행합니다. 에이전트는 해당 Git 동작을 명시적으로 요청받지 않으면 실행하지 않습니다.

## 완료와 보존

- 완료된 작업 디렉터리는 통째로 `tasks/finish/`로 옮깁니다.
- `tasks/finish/`는 완료 당시 판단과 진행 과정이며 현재 구현의 기준은 아닙니다.
- 중요한 완료 결과는 코딩 에이전트가 루트 `DEVLOG.md`에 요약합니다.
- 현재 규칙과 게임 사양은 `AGENTS.md`, `scsfp/docs/`, 실제 코드를 우선합니다.
