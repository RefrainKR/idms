## Overview
**Version**: 1.8.0

**Date**: 2026-01-23

## Problem Statement

기존 시스템에서 소숫점 반올림으로 인한 혼란:
- `0.0003%` → `0.000%` 표시 (실제 0이 아님)
- `99.9997%` → `100.000%` 표시 (실제 100%가 아님)
- 사용자가 정확한 값을 알 수 없음

## Solution

### 1. 새로운 Formatter 메서드 추가

#### `probabilityFraction(probability, decimals = 3)`
**용도**: 범례, 툴팁, 요약 - 정확한 확률 전달
**특징**: 분수 표기 지원

**로직**:
```javascript
if (probability === 0) return "0.000%";
if (probability >= 1) return "100.000%";

const percent = probability * 100;
const text = percent.toFixed(decimals);
const threshold = "0." + "0".repeat(decimals);

// 매우 낮은 확률은 분수로
if (text === threshold && probability > 0) {
    return `1/${Math.round(1/probability).toLocaleString()}`;
}
return text + "%";
```

**예시**:
- `0.000003` → `"1/333,333"` (정확한 분수)
- `0.00123` → `"0.123%"`
- `0.5` → `"50.000%"`

---

#### `probabilityBounded(probability, decimals = 3)`
**용도**: 차트 레이블, 모든 확률 표시 - 가독성 우선
**특징**: 화살표로 경계값 명시

**로직**:
```javascript
const percent = probability * 100;
const threshold = 1 / Math.pow(10, decimals);

if (percent === 0) return "0.000%";
if (percent >= 100) return "100.000%";

// 경계값: 표시 한계보다 작음
if (percent < threshold) {
    return `${threshold.toFixed(decimals)}%↓`;
}

// 경계값: 표시 한계보다 큼
if (percent > 100 - threshold) {
    return `${(100 - threshold).toFixed(decimals)}%↑`;
}

return `${percent.toFixed(decimals)}%`;
```

**예시**:
- `0.000003` → `"0.001%↓"` (0.001%보다 작음)
- `0.00123` → `"0.123%"`
- `0.999997` → `"99.999%↑"` (99.999%보다 큼)

## Design Decisions

### 1. Arrow Notation Selection
**선택**: `99.999%↑` (숫자 뒤에 화살표)

**이유**:
- ✅ 숫자 정렬 완벽 (시작 위치 일정)
- ✅ 시각적 직관성 (↓ = 더 작음, ↑ = 더 큼)
- ✅ 차트 가독성 우수
- ✅ 게임 UI 스타일 적합

**대안 비교**:
```
부등호 앞 배치:        화살표 뒤 배치:
< 0.001%              0.001%↓
  1.234%              1.234%
 50.000%             50.000%
> 99.999%            99.999%↑
```

### 2. Method Naming
**선택**: `probabilityFraction`, `probabilityBounded`

**이유**:
- `Formatter.probabilityFraction()` - 클래스명과 함께 사용 시 충분히 명확
- 너무 긴 이름 (`formatProbabilityFraction`) 방지
- 일관성: 모두 `probability*` 패턴

### 3. Backward Compatibility
**전략**: 별칭 메서드 제공

**장점**:
- 기존 코드 수정 불필요
- 점진적 마이그레이션 가능
- 테스트 코드 호환성 유지

## Impact Analysis

### User-Facing Changes

1. **차트 레이블**:
   - 경계값에 화살표 표시
   - 매우 낮은 확률도 명확하게 표시

   - 모든 확률이 Formatter 메서드 사용
   - 일관된 표기법
   - 경계값 혼란 제거
