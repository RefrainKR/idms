# 작업 문서 운영 규칙

이 디렉터리는 규모가 크거나 여러 단계로 진행되는 작업의 계획·결정·인수인계·검증 문서를 보관합니다.

## 역할

- **Sol 역할**: 아이디어 검토, 게임 규칙 해석, 범위와 완료 조건 결정, 실제 diff 최종 검토
- **Terra 역할**: 승인된 범위의 구현, 기계적 리팩토링, 테스트, 구현 결과 기록
- Terra가 규칙이나 범위를 확정할 수 없으면 추측하지 않고 `HANDOFF.md`의 미해결 질문에 기록한 뒤 Sol 역할로 반환합니다.

모델 버전이 바뀌어도 역할의 의미는 유지합니다. 현재 세션의 모델명보다 `BOARD.md`와 작업 문서에 기록된 현재 역할·상태가 우선합니다.

## 작업별 기본 파일

- `TASK.md`: 목적, 허용·금지 범위, 완료 조건, 브랜치
- `DECISIONS.md`: Sol 역할이 확정한 규칙과 설계 판단
- `HANDOFF.md`: 완료 사항, 남은 작업, 변경 파일, 검증, 질문, 다음 역할
- `RESULT.md`: 구현 및 최종 검토 결과

새 작업은 `_template/`을 복사해 작업별 디렉터리로 시작합니다.

## 상태 전이

`planning` → `ready-for-terra` → `implementing` → `ready-for-sol-review` → `changes-requested` → `done`

- 상태와 다음 역할은 `BOARD.md`와 해당 작업의 `TASK.md`에 함께 반영합니다.
- 역할을 바꾸기 전에 반드시 `HANDOFF.md`를 갱신합니다.
- 작업 문서에 아이디어가 있다는 사실만으로 구현이 승인된 것은 아닙니다.
- `done`은 코드·문서 반영과 필요한 검증, Sol 역할의 최종 검토가 모두 끝난 경우에만 사용합니다.

## Git 및 동시 작업

- 기본 방식은 하나의 작업 브랜치에서 Sol과 Terra가 순차적으로 소유권을 넘기는 것입니다.
- 같은 작업 트리의 같은 파일을 동시에 수정하지 않습니다.
- 실제 동시 구현은 사용자가 승인한 별도 브랜치와 별도 worktree에서만 진행하며, 먼저 파일 소유 범위를 분리합니다.
- 브랜치·worktree·커밋·병합은 사용자가 명시적으로 승인한 경우에만 수행합니다.

## 완료와 보존

- 완료된 작업 디렉터리는 통째로 `tasks/finish/`로 옮깁니다.
- `tasks/finish/`는 완료 당시의 판단과 진행 과정이며 현재 구현의 기준은 아닙니다.
- 중요한 완료 결과는 필요에 따라 `docs/UPDATE.md`에 요약합니다.
- 작업 문서가 아닌 폐기·대체된 일반 Markdown 문서는 필요한 경우 `docs/old/`에 보관합니다.
